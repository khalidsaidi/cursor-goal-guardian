# Release work

Before proposing release work or repeating validation, read `docs/release-status.md` and the relevant Git history.
Carry completed evidence forward unless a specific code change invalidates that behavior. A new commit alone does not invalidate prior tests.
Update that single release checklist when evidence changes. Do not grow a new checklist from individual fixes or restart completed studies.
The product helps an ordinary Cursor agent finish the user's goal. It is not an honesty detector or a system for catching deliberate bluff.
