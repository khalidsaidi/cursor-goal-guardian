# What has been checked

CGG is intended to help a normal Cursor agent finish the user's goal. Verification covers the goal loop, independent review and learning connections; it does not certify every task or input.

## Current platform scope

The current implementation has been built and run on Linux x64, including WSL Ubuntu connected to desktop Cursor. Earlier Windows/macOS artifacts and old platform matrices are not validation of this build.

## Real Cursor evidence

- Desktop checks exercised a temporary stop, retention of the original goal across a fresh chat, user resumption and completion with both independent checks.
- A native CLI case received useful findings, repaired unfinished work and completed with independent public-entry checks. That CLI did not emit the desktop continuation hook, so the result does not establish a desktop send-back round.
- Native reviews accepted completed work and caught a missing package-root export. In a later review, a controlled correction removed an unnecessary directory-path complaint while a genuine missing export was still caught.
- A historical qualified RRSI candidate was installed through CGG's automatic apply function; a subsequent native review received the installed prompt. The controller replaced search/trigger orchestration in that connection check.

## Earlier real-model learning evidence

Google's RRSI searched and accepted prompt changes with real Claude models in the lab. Inspected examples include removal of unnecessary complaints about supporting input validation. This remains useful evidence of prompt learning.

Historical whole-case flag counts do not establish that every label was valid or every useful finding was retained. One old bad-case flag concerned lint/supporting checks while both reviewers missed the actual public-export defect. Another case labelled finished lacked a public TypeScript export. Those limitations remain in the maintainer record; the corresponding blanket accuracy claims are not used.

## Local integration and packaging evidence

Local tests with stand-ins cover current goal coordination, captured work and check reuse, specific chat/panel feedback, RRSI selection guards and attribution, held-out qualification, adoption/undo, foreground yielding and shared allowances. The Linux x64 VSIX has also been built, installed and exercised through packaged offline end-to-end checks.

These checks verify software connections and controls. They are distinct from real-model behavior evidence and do not establish an additional real-user accuracy improvement.

## What is not established

- Correct completion or review accuracy for every future task.
- Improvement from naturally accumulated user feedback in ordinary projects.
- A fresh full feedback → RRSI search → automatic adoption sequence completed in one native Cursor run.
- Current Windows, macOS or ARM support.
- A general quality, speed or code-use percentage.

The agreed Linux/WSL release evidence is complete; a new winning prompt is not an additional release gate. Detailed provenance, revisions and limitations live in the [maintainer release record](release-status.md). Earlier versions of this document remain available in Git history.
