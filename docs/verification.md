# 1.0.0 verification record

Everything below was verified against **real artifacts and a real Cursor
editor** — no mocked-API claim stands in for any of it.

## Unit + contract tier (free, CI)
- ~200 tests across core/mcp/hook/extension; coverage thresholds enforced on core.
- Contract tests spawn the real MCP server (stdio) and the real built hook bundle.
- Quietness contract: one nudge per drift episode; quiet mode injects nothing, ever.

## End-to-end tier (real headless Cursor agents)
13 scenarios (`packages/e2e/scenarios/`), all green on the release commit:
on-goal completion, off-goal drift (with advisory proof — the off-goal file
landed), risky-command advisory, decision-gated switching, intent, progress
transitions, drift→realignment pairing, real AI judge (confirms drift,
dismisses false positives), migration of a real v0.4.11 workspace, panel
pipeline, quiet mode, uninstructed-agent anchoring (bare prompt, zero tool
instructions — the agent cooperated purely from the workspace rule), and a
packaged-binary smoke of the exact bin/ bundles the VSIX ships.

Bugs found only by this tier (all fixed): Cursor sends `mcp_server_name` (not
`server`), headless MCP tool calls need `--force`, judges stall without
`--trust`, a double-shebang crash lived only in the packaged MCP bundle, and
chained shell commands escaped prefix policy rules.

## Live editor tier (real Cursor, driven by PowerShell + CDP)
- Cursor's extension host logs: `Extension activated success:
  khalidsaidi.cursor-goal-guardian-extension` in a live window, no errors,
  2–4 ms activate call (the inertness contract holding in production).
- Command palette (screenshot-verified): all 14 Goal Guardian commands present
  and executable.
- Chrome DevTools Protocol against an instrumented Cursor instance
  (`--remote-debugging-port`), querying the real workbench DOM:
  - Explorer pane list contains **"Goal Guardian"** (default-visible in a
    fresh profile).
  - The resolved webview's DOM contains all 8 sections
    (`welcome/hero/pulse/board/drift/criteria/constraints/consent`); hero
    renders "On track · Finish the math utilities · ▶ add() has tests";
    board, criteria, and constraints all populated from the real state files.
  - Status bar item live: `target add() has tests · Goal Guardian - stable ·
    AI review off`.
- Note: a profile that has hidden all optional Explorer sections (Outline,
  Timeline, …) hides Goal Guardian with them; that is workbench preference,
  not extension behavior — fresh profiles show the view by default.

## Benchmarks
See `benchmarks.md` (generated by `node scripts/bench.mjs [--judge]`):
hook p95 71–77 ms spawn-to-response (~36 ms bare node startup), MCP round-trips
~2 ms, store 4.2 ms/dispatch with 195 ms replay of 1000 actions, lexical scorer
100% precision / 90% recall on the labeled set, real judge 20/20.

## Live interaction suite (real logged-in Cursor, driven end-to-end)

Every flow below was executed in a real Cursor window (CDP + UIAutomation +
real mouse/keyboard), with disk and DOM verified after each step:

1. **Complete active task** (panel button) → `COMPLETE_TASK` on the log,
   board re-rendered (Doing 0/To do 1/Done 1), status bar → "no active task".
2. **Start next task** (panel button) → state + status bar updated.
3. **Real hook drift** (installed extension's own binary): first drift nudged
   once, second same-episode drift stayed silent (quietness contract live);
   panel drift feed + consent card appeared via the file watcher.
4. **Enable AI review** (panel consent card) → background rescorer spawned the
   real cursor-agent judge from the extension host → both drifts confirmed
   (0.98/0.99) with correct rationales → verdicts cached + taped.
5. Panel showed "Drift confirmed", health Drifting, status bar `2⚠ · AI
   review on`.
6. **Realignment**: completing the task flipped entries to "confirmed —
   realigned ↩ COMPLETE_TASK", health Recovering, criteria checked done.
7. **Open Contract** command → real editor tab with v2 content.
8. **Hash guard + rebuild**: hand-tampered state.json; rebuild from the log
   restored the true goal (verified on disk and in the open editor).
9. **Uninstall** → native confirmation dialog clicked ("Remove") → guardian
   dir, rule, hook entries, and MCP entry all removed; panel dropped to the
   welcome state; status bar hidden.
10. **Setup wizard** → welcome button → 3 real input boxes + gitignore
    quickpick → SET_GOAL/ADD_TASKS/START_TASK on the log (replay invariant
    intact), 6 hook events + MCP wired to the installed binaries, anchoring
    rule written, .gitignore updated; panel + status bar live with the new
    goal.

Bugs this suite caught (fixed): test scaffolds seeded state without a
MIGRATE_IMPORT action (breaking `state === replay(actions)` — live rebuild
exposed it); the rebuild command swallowed errors (now surfaces a calm
warning); and a stale error dialog was found queue-blocking every subsequent
modal — dialog handling is now part of the live-test playbook.
